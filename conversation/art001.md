## ทำฉาก Battle "ป่ากลางคืน" แบบ 2.5D

**คำตอบสั้น:** ฉากควรเป็น 3D ครับ แต่ไม่ต้องปั้นโมเดลทุกชิ้น และ Blender MCP ไม่ควรเป็นวิธีหลัก วิธีที่เหมาะกับโปรเจกต์นี้คือ **ฉากแบบ diorama** ซึ่งมีองค์ประกอบดังนี้:
- **พื้น:** mesh 3D ทาเท็กซ์เจอร์ ส่วนนี้กินพื้นที่ภาพมากที่สุด
- **ของชิ้นเล็ก:** หิน หลุมศพ ศาลพระภูมิร้าง ทำเป็น 3D low-poly
- **ต้นไม้ พุ่มไม้ ต้นกล้วย ไผ่ และหมอก:** ใช้ภาพวาด 2D แปะบนแผ่น quad
- **ตัวละครและผี:** เป็น sprite แบบ billboard ตามแผนเดิม

ภาพ 背包修仙传 ที่แนบมาก็ใช้วิธีนี้ พื้นเป็นกระเบื้องและดิน 3D ส่วนต้นเมเปิลเป็นงานแนว painterly ที่ดูแบนเกือบ 2D เพราะกล้องมุมเฉียงประมาณ 50° มองเห็นพื้นเกือบทั้งจอ ส่วนต้นไม้มีหน้าที่หลักแค่เป็นกรอบรอบขอบ

### 1. ทำไมไม่ใช้ Blender MCP เป็นวิธีหลัก

| วิธี | ได้อะไร | ปัญหา | ใช้ตอนไหน |
|---|---|---|---|
| **Blender MCP** (ให้ AI สั่ง Blender) | ทำรูปทรงง่ายๆ เช่น หิน ป้ายหลุมศพ เสา และงานซ้ำๆ อย่าง decimate, ตั้ง pivot, export FBX | AI ปั้นโมเดลออร์แกนิก (ต้นไม้ ใบไม้) ได้ไม่สวย สไตล์ไม่คงที่ และเสียเวลามาก | งานเสริมหรืองาน batch |
| **AI สร้างโมเดลจากภาพ** (Tripo, Meshy, Hunyuan3D ฯลฯ) | ได้ของชิ้นเด่น เช่น ศาลพระภูมิหรือเจดีย์ร้าง | โพลีเยอะ topology เละ ต้องลดโพลีก่อนใช้ และต้องตรวจ license | ของ 2–3 ชิ้นที่เป็นจุดเด่นของฉาก |
| **AI วาดภาพ** (เท็กซ์เจอร์พื้นและภาพต้นไม้) | คุ้มที่สุด เพราะสิ่งที่ผู้เล่นเห็นเกือบทั้งจอคือพื้นกับต้นไม้ | ต้องคุมสไตล์ให้ทุกภาพเข้ากัน | **วิธีหลัก** |
| **Asset ฟรี CC0** (Kenney, Quaternius, Poly Haven, ambientCG) | ได้ placeholder ที่ดูดีทันที | สไตล์ไม่ไทย | ใช้ตอนทำ greybox และใช้ชั่วคราว |
| **Coding agent เขียน Editor script วางฉาก** | ฉากสร้างซ้ำได้ ควบคุมด้วย seed และเข้ากับกฎ "สร้างฉากผ่าน Editor API" ที่คุณตั้งไว้แล้ว | agent มองไม่เห็นความสวย ต้องดูจากภาพที่จับไว้ | **ใช้วางฉากทั้งหมด** |

**สรุปการแบ่งงาน:** คุณ (หรือ AI วาดภาพ) ทำ "ชิ้นส่วนภาพ" ส่วน coding agent ประกอบฉาก ตั้งแสง และวัด performance

### 2. ลำดับขั้นตอนที่แนะนำ

**ขั้น 0: ล็อกกล้องก่อนทำอย่างอื่น**
ทุกอย่างในฉากขึ้นกับมุมกล้อง ถ้าเปลี่ยนกล้องทีหลังต้องทำภาพต้นไม้ใหม่ทั้งหมด ค่าที่แนะนำ:
- Perspective, FOV ประมาณ 30–35° (แคบไว้เพื่อลดการบิดของภาพ), pitch 50°, ระยะจากผู้เล่นประมาณ 18–22 หน่วย
- กล้อง**ไม่หมุนแกน Y** ภาพต้นไม้จึงหันตามมุมกล้องครั้งเดียวตอนวางได้เลย ไม่ต้องคำนวณ billboard ทุกเฟรม
- ถ้า ADR ของ Stage 08 เลือก orthographic ไว้แล้วก็ใช้ตามนั้นได้ หลักการที่เหลือเหมือนกัน

**ขั้น 1: ทำภาพเป้าหมาย 1 ภาพ (key art)**
ใช้ AI วาดภาพหน้าจอเกมในมุมกล้องที่ล็อกไว้ ภาพนี้ใช้เป็นเป้าหมายและเป็น style reference ให้ภาพอื่นทุกภาพ
> *Top-down 50 degree view of a Thai haunted forest clearing at night, moonlight, banana trees, bamboo, old abandoned spirit house, broken graves, mist, faint green will-o-wisps, painterly hand-painted game art, dark blue palette with warm lantern light in center, clear empty ground in the middle for gameplay*

**ขั้น 2: Greybox (agent ทำได้ทันที)**
วางพื้นและ primitive แทนต้นไม้กับหิน ใส่ศัตรู 300 ตัว แล้วเช็กแค่ 2 เรื่อง คือ**มองเห็นศัตรูชัดไหม** และ**ขนาดสนามพอดีไหม**

**ขั้น 3: พื้น (สำคัญที่สุด เพราะกินพื้นที่จอประมาณ 70%)**
- ใช้เท็กซ์เจอร์แบบต่อกันไร้รอยต่อ (seamless) 3–4 แบบ ได้แก่ ดินชื้น, หญ้าแห้ง, ใบไม้ร่วง และทางดินหรือหินเก่า
- ทำ shader (Shader Graph) ผสมเท็กซ์เจอร์ด้วย vertex color หรือ mask
- เพิ่ม macro variation คือ noise ขนาดใหญ่ทับอีกชั้น เพื่อไม่ให้เห็นลายซ้ำ
- โปรย decal เช่น รากไม้ ใบไม้กองเล็ก และวงยันต์จางๆ
- **คุมค่าความสว่างพื้นให้มืดถึงกลางและคอนทราสต์ต่ำ** เพราะพื้นเป็นฉากหลัง ตัวละครต้องเด่นกว่า

**ขั้น 4: ชุด props (ประมาณ 15–25 ชิ้น)**

| ประเภท | ชิ้นที่แนะนำ (ธีมป่าไทยกลางคืน) |
|---|---|
| ภาพบน quad (ภาพวาด) | ต้นกล้วย 2–3 แบบ (บ้านของนางตานี), กอไผ่, ต้นโพธิ์/ไทรผูกผ้าสามสี, พุ่มไม้, กอหญ้า, เถาวัลย์, ม่านหมอก |
| 3D low-poly | หิน 3–4 แบบ, ตอไม้, หลุมศพหรือเจดีย์บรรจุอัฐิพัง, ศาลพระภูมิร้าง (ชิ้นเด่น), ศาลาไม้ผุ, เสาธงตะขาบขาด, ไหแตก |
| เอฟเฟกต์ | หิ่งห้อย, ผีพรายไฟสีเขียว, ธูปเทียนมีแสงวูบวาบ, ใบไม้ปลิว |

**ขั้น 5: ขอบสนาม**
เกม survivor ต้องมีขอบเขต วิธีที่นิยมคือทำสนามปิดแบบเกมอ้างอิง เช่น ขนาดประมาณ 50×50 หน่วย ขอบรอบนอกให้ต้นไม้ขึ้นแน่นเป็นกำแพง ซ้อนชั้นหมอก และไล่สีให้มืดลงเรื่อยๆ ผู้เล่นจะรู้สึกว่าเดินต่อไม่ได้เพราะป่ารก ไม่ใช่เพราะเจอกำแพงล่องหน

> **ข้อควรระวัง:** ขนาดสนามเป็น**กฎเกม** ตัว Simulation ต้องรู้ขอบเขตด้วย ถ้า Core ยังไม่มีค่า arena bounds ให้ทำเป็นงานแยก (แก้ data และ Core) อย่าให้ฉากเป็นตัวกำหนดเอง

**ขั้น 6: แสงกลางคืนที่ยังเล่นได้ (จุดที่พังบ่อยที่สุด)**
ฉากกลางคืนมักมืดจนมองไม่เห็นศัตรู แก้ได้ดังนี้:
- **แสงจันทร์:** directional light สีฟ้าอมม่วง ความเข้มต่ำ เปิด shadow ความละเอียดต่ำตัวเดียว
- **ambient:** สีน้ำเงินเข้ม ไม่ใช้ดำสนิท
- **ผีเรืองแสงจางๆ:** ใส่ rim หรือ emissive บน sprite ผี ซึ่งเข้ากับธีมด้วย เพราะผีไทยในความเชื่อก็มักมีแสง (เช่น ไส้กระสือเรืองแสง)
- **ไฟปลอม:** เทียน ผีพราย และหิ่งห้อย ใช้ sprite แบบ additive ร่วมกับ bloom **ไม่ต้องใช้ light จริง** เพราะ URP บน Web มีงบ additional light ต่อ object จำกัด
- **ของที่อยู่นิ่ง:** bake lightmap ไปเลย
- **Fog:** ใช้ linear fog ของ URP กับม่านหมอกที่เป็นภาพวาด
- **Post-processing:** Bloom, Vignette (ทำให้ขอบจอมืด ช่วยดึงสายตาเข้ากลางจอ) และ Color Adjustments ควรมีสวิตช์ปิดใน settings เผื่อเครื่องอ่อน

**ขั้น 7: วาง sprite ตัวละครในฉาก 3D**
- quad หันตามมุมกล้อง ใช้ alpha clip และให้จุด pivot อยู่ที่เท้า
- ใช้ blob shadow (วงรีมืดใต้เท้า) แทนการให้ sprite ทอดเงาจริง ทั้งถูกกว่าและอ่านง่ายกว่า
- ต้นไม้ที่อยู่ด้านหน้าและบังผู้เล่น ให้ใช้ dither หรือทำโปร่งใสเมื่ออยู่ระหว่างกล้องกับผู้เล่น (ถ้าวางต้นไม้แค่ที่ขอบสนามก็แทบไม่ต้องทำ)

**งบ performance สำหรับ Web (ให้ agent วัดเทียบ):**
- draw calls/batches ไม่เกินประมาณ 150–200
- เท็กซ์เจอร์ฉากรวม atlas และกำหนด max size ไม่เกิน 2048
- props ตั้งเป็น static batching ส่วนหญ้าใช้ GPU instancing

### 3. วิธีให้ AI วาดชิ้นส่วนภาพ (คุณทำเอง)

1. **ล็อกสไตล์:** แนบ key art จากขั้น 1 เป็น style reference ทุกครั้ง
2. **ภาพบน quad (ต้นไม้/พุ่มไม้):** สั่งวาดบนพื้นหลังสีเรียบ แล้วลบพื้นหลังออก ตัวอย่าง prompt:
   > *Single Thai banana tree, painterly hand-painted game asset, viewed from 50 degree high angle, night moonlight rim light, isolated on plain flat green background, no shadow on ground*
3. **เท็กซ์เจอร์พื้น:**
   > *Seamless tileable texture, dark damp forest soil with dry leaves, top-down, painterly, night palette, no lighting direction*

   ถ้ายังเห็นรอยต่อ แก้ด้วย offset แล้วระบายทับ (ทำได้ทั้งใน Krita และ Photoshop)
4. **ตั้งชื่อไฟล์ตามรูปแบบแล้ววางใน `Assets/Main/Art/Environment/ForestNight/Incoming/`** เช่น `card_banana_01.png`, `ground_soil.png`, `prop_spirit_house.fbx` จากนั้น agent จะนำเข้าและแทนที่ placeholder ให้
5. **บันทึกที่มาและ license** ของทุกชิ้นลงไฟล์ attribution (เป็นข้อกำหนดของ Stage 13 อยู่แล้ว)

### 4. Prompt สำหรับ Coding Agent

แบ่งเป็น 2 stage ตามกฎใหม่ของคุณ (ไม่เกิน 7 ข้อต่อ stage และไม่แตะหลายชั้นพร้อมกัน)

**Stage 08b: Battle Environment Greybox, กล้อง และแสง**
```text
ทำ Stage 08b เท่านั้น: ฉาก Battle "ป่ากลางคืน" ระดับ greybox (Presentation เท่านั้น)
ห้ามแก้ Core, data/ หรือกติกาเกม ตรวจงานด้วยภาพจาก Editor (-Suite Fast) ไม่ต้อง build Web ระหว่างทำ

1. สำรวจก่อนแก้: กล้อง, ADR ของ Stage 08, ขนาดสนามที่ Simulation ใช้จริง (ถ้า Core ไม่มี arena bounds
   ให้หยุดและรายงานข้อเสนอเป็นงานแยก ห้ามกำหนดขอบเขตจากฝั่งฉาก) และจับภาพ "ก่อนแก้"
2. ล็อกกล้อง: perspective FOV 30–35°, pitch 50°, ไม่หมุนแกน Y, ตามผู้เล่นแบบ smooth
   เก็บค่าใน ScriptableObject (CameraProfile) และอัปเดต ADR เดิมถ้าค่าต่างจากเดิม
3. ArenaTheme (ScriptableObject) + Editor script ArenaBuilder (เมนูและ -executeMethod):
   สร้างฉากจาก theme + seed ได้ทุกครั้งโดยไม่ต้องวางมือ ประกอบด้วย ground mesh, วงขอบป่าทึบ,
   props ด้านในแบบเบาบาง และพื้นที่ว่างกลางสนาม; ผลลัพธ์เป็น prefab Arena_ForestNight
   props เป็นภาพเท่านั้น ไม่มี collider ที่มีผลต่อ gameplay
4. Ground shader (Shader Graph, URP): ผสมเท็กซ์เจอร์ 3 ชั้นด้วย vertex color/mask + macro noise
   ถ้า Art/Environment/ForestNight/ ยังไม่มีเท็กซ์เจอร์ ให้ใช้สี placeholder แล้วสลับเป็นภาพได้โดยไม่แก้โค้ด
5. แสงกลางคืน: moon directional (shadow ความละเอียดต่ำ), ambient น้ำเงินเข้ม, fog, point light ตะเกียงตามผู้เล่น
   (realtime light หลักดวงเดียว), ไฟปลอมเป็น additive sprite, bake lightmap ของ static props,
   post (Bloom/Vignette/Color Adjustments) มีสวิตช์ปิดได้
6. sprite ใน 3D: billboard ตามมุมกล้อง, pivot ที่เท้า, alpha clip, blob shadow
   ศัตรูและ pickup ต้องอ่านออกบนพื้นมืด (ใช้ rim/emissive)
7. หลักฐาน: จับภาพ 1920×1080 และ 1280×720 (ว่าง / 300 ศัตรู) ลง artifacts/ui/battle-env/
   บันทึก batches, draw calls และ ms/frame ใน Editor

Acceptance:
- สร้างฉากใหม่จาก ArenaBuilder ได้ผลเหมือนเดิมเมื่อใช้ seed เดิม
- ในภาพที่มีศัตรู 300 ตัว ผู้เล่น ศัตรู และ pickup แยกจากพื้นได้ชัด (ตรวจ luminance contrast อัตโนมัติถ้าทำได้)
- batches ≤ 200 และไม่มีการแก้ Core หรือ data
- รายงานสั้นตามรูปแบบใหม่ PASS / FAIL / NOT RUN
```

**Stage 08c: นำเข้า Art จริง (ทำหลังจากคุณวางไฟล์ภาพแล้ว)**
```text
ทำ Stage 08c เท่านั้น: นำเข้า art ของฉากป่ากลางคืนจาก Art/Environment/ForestNight/Incoming/
ห้ามแก้ Core, data/ หรือกติกาเกม

1. ตรวจไฟล์ตามรูปแบบชื่อ (ground_*, card_*, prop_*, fx_*) และรายงานไฟล์ที่ชื่อผิดหรือขาด
2. ตั้ง import settings: max size ≤ 2048, compression ที่เหมาะกับ Web, mipmap สำหรับพื้น,
   alpha clip สำหรับภาพ card; รวม card เป็น atlas
3. สร้าง prefab ของ card (quad หันตามมุมกล้อง) และ prop (ตั้ง scale/pivot) แล้วผูกเข้า ArenaTheme
4. สร้างฉากใหม่ด้วย ArenaBuilder แล้ว bake lighting ใหม่
5. อัปเดต attribution/license ของ asset ทุกชิ้น
6. จับภาพก่อนและหลังเทียบกับ key art แล้ววัด batches/ms เทียบกับ 08b

Acceptance: ไม่มี placeholder เหลือในภาพหลักฐาน, batches ยังอยู่ในงบ, ทุก asset มี attribution
และตอนปิด stage build Web (-Suite Full) แล้วฉากแสดงผลถูกต้อง
```

### 5. ลำดับงานที่แนะนำ

1. **ส่ง Stage 08b ได้ทันที** โดยใช้ placeholder ทั้งหมด จะได้ล็อกกล้อง แสง และการมองเห็นศัตรูก่อน
2. ระหว่างที่ agent ทำ 08b คุณทำ key art และวาดชิ้นส่วนภาพประมาณ 10–15 ชิ้นไปพร้อมกัน
3. ส่ง Stage 08c ตอนภาพพร้อม
4. Blender MCP ค่อยใช้ทีหลังกับงานเฉพาะ เช่น ทำหินหรือหลุมศพ low-poly หลายแบบ หรือ batch ลดโพลีของโมเดลที่ได้จาก AI แปลงภาพเป็น 3D

**อีกเรื่องที่ควรรู้:** ภาพในเกมตอนนี้ยังห่างจากเกมอ้างอิงมากเพราะ**ยังไม่มี art จริงเลยสักชิ้น** ไม่ใช่เพราะสถาปัตยกรรมผิด หน้าจอ Camp ก็เป็นแบบเดียวกัน คือ layout อาจใช้ได้แล้ว แต่ยังเป็นกล่องสีเปล่า ถ้าจะทำต่อ ผมเสนอให้ทำ "UI art kit" เป็นงานถัดไป (กรอบม้วนกระดาษ ปุ่ม ป้ายราคา ช่อง grid) ด้วยวิธีเดียวกัน คือ AI วาดชิ้นส่วนแล้ว agent นำไปตั้งเป็น 9-slice

ถ้าต้องการ ผมร่างชุด prompt สำหรับวาดชิ้นส่วนภาพทั้งหมดให้ได้ครับ ทั้งต้นไม้ พื้น props และ UI kit โดยคุมสไตล์ให้เป็นชุดเดียวกัน

## ทำฉาก Battle "ป่ากลางคืน" แบบ 2.5D

**คำตอบสั้น:** ฉากควรเป็น 3D ครับ แต่ไม่ต้องปั้นโมเดลทุกชิ้น และ Blender MCP ไม่ควรเป็นวิธีหลัก วิธีที่เหมาะกับโปรเจกต์นี้คือ **ฉากแบบ diorama** ซึ่งมีองค์ประกอบดังนี้:
- **พื้น:** mesh 3D ทาเท็กซ์เจอร์ ส่วนนี้กินพื้นที่ภาพมากที่สุด
- **ของชิ้นเล็ก:** หิน หลุมศพ ศาลพระภูมิร้าง ทำเป็น 3D low-poly
- **ต้นไม้ พุ่มไม้ ต้นกล้วย ไผ่ และหมอก:** ใช้ภาพวาด 2D แปะบนแผ่น quad
- **ตัวละครและผี:** เป็น sprite แบบ billboard ตามแผนเดิม

ภาพ 背包修仙传 ที่แนบมาก็ใช้วิธีนี้ พื้นเป็นกระเบื้องและดิน 3D ส่วนต้นเมเปิลเป็นงานแนว painterly ที่ดูแบนเกือบ 2D เพราะกล้องมุมเฉียงประมาณ 50° มองเห็นพื้นเกือบทั้งจอ ส่วนต้นไม้มีหน้าที่หลักแค่เป็นกรอบรอบขอบ

### 1. ทำไมไม่ใช้ Blender MCP เป็นวิธีหลัก

| วิธี | ได้อะไร | ปัญหา | ใช้ตอนไหน |
|---|---|---|---|

| **AI สร้างโมเดลจากภาพ** (Tripo, Meshy, Hunyuan3D ฯลฯ) | ได้ของชิ้นเด่น เช่น ศาลพระภูมิหรือเจดีย์ร้าง | โพลีเยอะ topology เละ ต้องลดโพลีก่อนใช้ และต้องตรวจ license | ของ 2–3 ชิ้นที่เป็นจุดเด่นของฉาก |

| **Asset ฟรี CC0** (Kenney, Quaternius, Poly Haven, ambientCG) | ได้ placeholder ที่ดูดีทันที | สไตล์ไม่ไทย | ใช้ตอนทำ greybox และใช้ชั่วคราว |

**สรุปการแบ่งงาน:** คุณ (หรือ AI วาดภาพ) ทำ "ชิ้นส่วนภาพ" ส่วน coding agent ประกอบฉาก ตั้งแสง และวัด performance

### 2. ลำดับขั้นตอนที่แนะนำ

**ขั้น 0: ล็อกกล้องก่อนทำอย่างอื่น**
ทุกอย่างในฉากขึ้นกับมุมกล้อง ถ้าเปลี่ยนกล้องทีหลังต้องทำภาพต้นไม้ใหม่ทั้งหมด ค่าที่แนะนำ:
- Perspective, FOV ประมาณ 30–35° (แคบไว้เพื่อลดการบิดของภาพ), pitch 50°, ระยะจากผู้เล่นประมาณ 18–22 หน่วย
- กล้อง**ไม่หมุนแกน Y** ภาพต้นไม้จึงหันตามมุมกล้องครั้งเดียวตอนวางได้เลย ไม่ต้องคำนวณ billboard ทุกเฟรม
- ถ้า ADR ของ Stage 08 เลือก orthographic ไว้แล้วก็ใช้ตามนั้นได้ หลักการที่เหลือเหมือนกัน

**ขั้น 1: ทำภาพเป้าหมาย 1 ภาพ (key art)**
ใช้ AI วาดภาพหน้าจอเกมในมุมกล้องที่ล็อกไว้ ภาพนี้ใช้เป็นเป้าหมายและเป็น style reference ให้ภาพอื่นทุกภาพ
> *Top-down 50 degree view of a Thai haunted forest clearing at night, moonlight, banana trees, bamboo, old abandoned spirit house, broken graves, mist, faint green will-o-wisps, painterly hand-painted game art, dark blue palette with warm lantern light in center, clear empty ground in the middle for gameplay*

**ขั้น 2: Greybox (agent ทำได้ทันที)**
วางพื้นและ primitive แทนต้นไม้กับหิน ใส่ศัตรู 300 ตัว แล้วเช็กแค่ 2 เรื่อง คือ**มองเห็นศัตรูชัดไหม** และ**ขนาดสนามพอดีไหม**

**ขั้น 3: พื้น (สำคัญที่สุด เพราะกินพื้นที่จอประมาณ 70%)**
- ใช้เท็กซ์เจอร์แบบต่อกันไร้รอยต่อ (seamless) 3–4 แบบ ได้แก่ ดินชื้น, หญ้าแห้ง, ใบไม้ร่วง และทางดินหรือหินเก่า
- ทำ shader (Shader Graph) ผสมเท็กซ์เจอร์ด้วย vertex color หรือ mask
- เพิ่ม macro variation คือ noise ขนาดใหญ่ทับอีกชั้น เพื่อไม่ให้เห็นลายซ้ำ
- โปรย decal เช่น รากไม้ ใบไม้กองเล็ก และวงยันต์จางๆ
- **คุมค่าความสว่างพื้นให้มืดถึงกลางและคอนทราสต์ต่ำ** เพราะพื้นเป็นฉากหลัง ตัวละครต้องเด่นกว่า

**ขั้น 4: ชุด props (ประมาณ 15–25 ชิ้น)**

| ประเภท | ชิ้นที่แนะนำ (ธีมป่าไทยกลางคืน) |
|---|---|
| ภาพบน quad (ภาพวาด) | ต้นกล้วย 2–3 แบบ (บ้านของนางตานี), กอไผ่, ต้นโพธิ์/ไทรผูกผ้าสามสี, พุ่มไม้, กอหญ้า, เถาวัลย์, ม่านหมอก |
| 3D low-poly | หิน 3–4 แบบ, ตอไม้, หลุมศพหรือเจดีย์บรรจุอัฐิพัง, ศาลพระภูมิร้าง (ชิ้นเด่น), ศาลาไม้ผุ, เสาธงตะขาบขาด, ไหแตก |
| เอฟเฟกต์ | หิ่งห้อย, ผีพรายไฟสีเขียว, ธูปเทียนมีแสงวูบวาบ, ใบไม้ปลิว |

**ขั้น 5: ขอบสนาม**
เกม survivor ต้องมีขอบเขต วิธีที่นิยมคือทำสนามปิดแบบเกมอ้างอิง เช่น ขนาดประมาณ 50×50 หน่วย ขอบรอบนอกให้ต้นไม้ขึ้นแน่นเป็นกำแพง ซ้อนชั้นหมอก และไล่สีให้มืดลงเรื่อยๆ ผู้เล่นจะรู้สึกว่าเดินต่อไม่ได้เพราะป่ารก ไม่ใช่เพราะเจอกำแพงล่องหน

> **ข้อควรระวัง:** ขนาดสนามเป็น**กฎเกม** ตัว Simulation ต้องรู้ขอบเขตด้วย ถ้า Core ยังไม่มีค่า arena bounds ให้ทำเป็นงานแยก (แก้ data และ Core) อย่าให้ฉากเป็นตัวกำหนดเอง

**ขั้น 6: แสงกลางคืนที่ยังเล่นได้ (จุดที่พังบ่อยที่สุด)**
ฉากกลางคืนมักมืดจนมองไม่เห็นศัตรู แก้ได้ดังนี้:
- **แสงจันทร์:** directional light สีฟ้าอมม่วง ความเข้มต่ำ เปิด shadow ความละเอียดต่ำตัวเดียว
- **ambient:** สีน้ำเงินเข้ม ไม่ใช้ดำสนิท
- **ตะเกียงพ่อหมอ:** point light สีส้มอุ่นตามตัวผู้เล่น รัศมีประมาณ 6–8 หน่วย ใช้เป็น realtime light หลักแค่ดวงเดียว
- **ผีเรืองแสงจางๆ:** ใส่ rim หรือ emissive บน sprite ผี ซึ่งเข้ากับธีมด้วย เพราะผีไทยในความเชื่อก็มักมีแสง (เช่น ไส้กระสือเรืองแสง)
- **ไฟปลอม:** เทียน ผีพราย และหิ่งห้อย ใช้ sprite แบบ additive ร่วมกับ bloom **ไม่ต้องใช้ light จริง** เพราะ URP บน Web มีงบ additional light ต่อ object จำกัด
- **ของที่อยู่นิ่ง:** bake lightmap ไปเลย
- **Fog:** ใช้ linear fog ของ URP กับม่านหมอกที่เป็นภาพวาด
- **Post-processing:** Bloom, Vignette (ทำให้ขอบจอมืด ช่วยดึงสายตาเข้ากลางจอ) และ Color Adjustments ควรมีสวิตช์ปิดใน settings เผื่อเครื่องอ่อน

**ขั้น 7: วาง sprite ตัวละครในฉาก 3D**
- quad หันตามมุมกล้อง ใช้ alpha clip และให้จุด pivot อยู่ที่เท้า
- ใช้ blob shadow (วงรีมืดใต้เท้า) แทนการให้ sprite ทอดเงาจริง ทั้งถูกกว่าและอ่านง่ายกว่า
- ต้นไม้ที่อยู่ด้านหน้าและบังผู้เล่น ให้ใช้ dither หรือทำโปร่งใสเมื่ออยู่ระหว่างกล้องกับผู้เล่น (ถ้าวางต้นไม้แค่ที่ขอบสนามก็แทบไม่ต้องทำ)

**งบ performance สำหรับ Web (ให้ agent วัดเทียบ):**
- draw calls/batches ไม่เกินประมาณ 150–200
- เท็กซ์เจอร์ฉากรวม atlas และกำหนด max size ไม่เกิน 2048
- props ตั้งเป็น static batching ส่วนหญ้าใช้ GPU instancing

### 3. วิธีให้ AI วาดชิ้นส่วนภาพ (คุณทำเอง)

1. **ล็อกสไตล์:** แนบ key art จากขั้น 1 เป็น style reference ทุกครั้ง
2. **ภาพบน quad (ต้นไม้/พุ่มไม้):** สั่งวาดบนพื้นหลังสีเรียบ แล้วลบพื้นหลังออก ตัวอย่าง prompt:
   > *Single Thai banana tree, painterly hand-painted game asset, viewed from 50 degree high angle, night moonlight rim light, isolated on plain flat green background, no shadow on ground*
3. **เท็กซ์เจอร์พื้น:**
   > *Seamless tileable texture, dark damp forest soil with dry leaves, top-down, painterly, night palette, no lighting direction*

   ถ้ายังเห็นรอยต่อ แก้ด้วย offset แล้วระบายทับ (ทำได้ทั้งใน Krita และ Photoshop)
4. **ตั้งชื่อไฟล์ตามรูปแบบแล้ววางใน `Assets/Main/Art/Environment/ForestNight/Incoming/`** เช่น `card_banana_01.png`, `ground_soil.png`, `prop_spirit_house.fbx` จากนั้น agent จะนำเข้าและแทนที่ placeholder ให้
5. **บันทึกที่มาและ license** ของทุกชิ้นลงไฟล์ attribution (เป็นข้อกำหนดของ Stage 13 อยู่แล้ว)

### 4. Prompt สำหรับ Coding Agent

แบ่งเป็น 2 stage ตามกฎใหม่ของคุณ (ไม่เกิน 7 ข้อต่อ stage และไม่แตะหลายชั้นพร้อมกัน)

**Stage 08b: Battle Environment Greybox, กล้อง และแสง**
```text
ทำ Stage 08b เท่านั้น: ฉาก Battle "ป่ากลางคืน" ระดับ greybox (Presentation เท่านั้น)
ห้ามแก้ Core, data/ หรือกติกาเกม ตรวจงานด้วยภาพจาก Editor (-Suite Fast) ไม่ต้อง build Web ระหว่างทำ

1. สำรวจก่อนแก้: กล้อง, ADR ของ Stage 08, ขนาดสนามที่ Simulation ใช้จริง (ถ้า Core ไม่มี arena bounds
   ให้หยุดและรายงานข้อเสนอเป็นงานแยก ห้ามกำหนดขอบเขตจากฝั่งฉาก) และจับภาพ "ก่อนแก้"
2. ล็อกกล้อง: perspective FOV 30–35°, pitch 50°, ไม่หมุนแกน Y, ตามผู้เล่นแบบ smooth
   เก็บค่าใน ScriptableObject (CameraProfile) และอัปเดต ADR เดิมถ้าค่าต่างจากเดิม
3. ArenaTheme (ScriptableObject) + Editor script ArenaBuilder (เมนูและ -executeMethod):
   สร้างฉากจาก theme + seed ได้ทุกครั้งโดยไม่ต้องวางมือ ประกอบด้วย ground mesh, วงขอบป่าทึบ,
   props ด้านในแบบเบาบาง และพื้นที่ว่างกลางสนาม; ผลลัพธ์เป็น prefab Arena_ForestNight
   props เป็นภาพเท่านั้น ไม่มี collider ที่มีผลต่อ gameplay
4. Ground shader (Shader Graph, URP): ผสมเท็กซ์เจอร์ 3 ชั้นด้วย vertex color/mask + macro noise
   ถ้า Art/Environment/ForestNight/ ยังไม่มีเท็กซ์เจอร์ ให้ใช้สี placeholder แล้วสลับเป็นภาพได้โดยไม่แก้โค้ด
5. แสงกลางคืน: moon directional (shadow ความละเอียดต่ำ), ambient น้ำเงินเข้ม, fog, point light ตะเกียงตามผู้เล่น
   (realtime light หลักดวงเดียว), ไฟปลอมเป็น additive sprite, bake lightmap ของ static props,
   post (Bloom/Vignette/Color Adjustments) มีสวิตช์ปิดได้
6. sprite ใน 3D: billboard ตามมุมกล้อง, pivot ที่เท้า, alpha clip, blob shadow
   ศัตรูและ pickup ต้องอ่านออกบนพื้นมืด (ใช้ rim/emissive)
7. หลักฐาน: จับภาพ 1920×1080 และ 1280×720 (ว่าง / 300 ศัตรู) ลง artifacts/ui/battle-env/
   บันทึก batches, draw calls และ ms/frame ใน Editor

Acceptance:
- สร้างฉากใหม่จาก ArenaBuilder ได้ผลเหมือนเดิมเมื่อใช้ seed เดิม
- ในภาพที่มีศัตรู 300 ตัว ผู้เล่น ศัตรู และ pickup แยกจากพื้นได้ชัด (ตรวจ luminance contrast อัตโนมัติถ้าทำได้)
- batches ≤ 200 และไม่มีการแก้ Core หรือ data
- รายงานสั้นตามรูปแบบใหม่ PASS / FAIL / NOT RUN
```

**Stage 08c: นำเข้า Art จริง (ทำหลังจากคุณวางไฟล์ภาพแล้ว)**
```text
ทำ Stage 08c เท่านั้น: นำเข้า art ของฉากป่ากลางคืนจาก Art/Environment/ForestNight/Incoming/
ห้ามแก้ Core, data/ หรือกติกาเกม

1. ตรวจไฟล์ตามรูปแบบชื่อ (ground_*, card_*, prop_*, fx_*) และรายงานไฟล์ที่ชื่อผิดหรือขาด
2. ตั้ง import settings: max size ≤ 2048, compression ที่เหมาะกับ Web, mipmap สำหรับพื้น,
   alpha clip สำหรับภาพ card; รวม card เป็น atlas
3. สร้าง prefab ของ card (quad หันตามมุมกล้อง) และ prop (ตั้ง scale/pivot) แล้วผูกเข้า ArenaTheme
4. สร้างฉากใหม่ด้วย ArenaBuilder แล้ว bake lighting ใหม่
5. อัปเดต attribution/license ของ asset ทุกชิ้น
```

## ฉาก Battle สไตล์ "ป่าการ์ตูนเส้นหนา ยามค่ำคืน"

**AI ช่วยได้เกือบทั้งหมด แต่ยังทำเองอัตโนมัติ 100% ไม่ได้** ข่าวดีคือสไตล์ในภาพที่แนบเหมาะกับ AI มากกว่าแผนเดิม เพราะดูจากภาพแล้ว ต้นไม้ พุ่มไม้ หิน และของประดับเกือบทุกชิ้นเป็น**ภาพวาด 2D ที่ตั้งอยู่ในโลก 3D** แทบไม่มีโมเดล 3D เลย งานจึงเหลือแค่ "วาดภาพ" กับ "ประกอบฉาก" ซึ่ง AI สองฝั่งทำได้ดี

| งาน | ใครทำ | AI ทำได้แค่ไหน |
|---|---|---|
| วาดชิ้นส่วนภาพ (ต้นไม้ พุ่ม หญ้า หิน คราบดิน) | AI วาดภาพ | ประมาณ 70–80% ส่วนที่เหลือคุณต้องคัดภาพ ลบพื้นหลัง และแก้เส้นที่หลุด |

| ตัดสินว่า "สวยแล้วหรือยัง" | **คุณ** | AI ทำแทนไม่ได้ |

> **ข้อควรระวัง:** อย่าใส่ชื่อเกม "Cult of the Lamb" ลงใน prompt วาดภาพ และอย่าใช้ภาพจากเกมเป็น reference ตรงๆ เพราะเสี่ยงเรื่องลิขสิทธิ์และทำให้เกมดูเหมือนก๊อปมา ให้อธิบาย**ลักษณะ**ของสไตล์แทน (ดูข้อ 4)

## 1. ให้ Gemini 4 Argon วาดทั้งฉากได้ไหม

**ให้ Argon วาดภาพเองโดยตรงไม่ได้ครับ** ข้อมูลของ API บอกว่า Argon รับภาพ วิดีโอ เสียง และ PDF ได้ แต่ส่งออกเป็นข้อความเท่านั้น และไม่รองรับการสร้างภาพ [therundown](https://www.therundown.ai/tools/gemini-4-argon) งานภาพที่เห็นในเดโมเกิดจากการที่ Argon ทำงานใน Antigravity หรือแอป Gemini แล้วเรียก **Nano Banana** มาวาดให้อีกที [blog](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-argon/) ถ้าคุณใช้ผ่านแอป Gemini อยู่ อาจสั่งได้ว่า "วาดให้หน่อย" แต่ตัวที่วาดจริงคือ Nano Banana

แม้จะให้ Nano Banana วาดทั้งฉากออกมาเป็นภาพเดียว ก็**ยังเอาไปใช้เป็นฉากเล่นในเกมไม่ได้** เพราะ:

| ปัญหา | เหตุผล |
|---|---|
| สนามใหญ่กว่าจอ | กล้องเลื่อนตามผู้เล่น ภาพเดียวจึงต้องกว้างหลายเท่าของจอ แต่ AI วาดได้แค่ราว 1–2K px |
| ตัวละครต้องเดินอ้อมหลังต้นไม้ได้ | ภาพแบนไม่มีความลึก ผีจะลอยทับต้นไม้ตลอดเวลา |
| กล้อง perspective | เดินไปแล้วภาพแบนจะไม่ขยับตามมุมเหมือนของ 3D ทำให้ฉากดูเหมือนสติกเกอร์ |
| ต้องเปลี่ยนกลางวัน/กลางคืน และทำแสงตะเกียง | ภาพที่วาดแสงฝังไว้แล้ว แก้แสงทีหลังไม่ได้ |
| ต้องสุ่มฉากด้วย seed และแบ่งโซนความรก | ภาพเดียวตายตัว แก้ส่วนไหนต้องวาดใหม่ทั้งภาพ |

### วิธีใช้เครดิต 1 ชั่วโมงต่อวันให้คุ้ม

ใช้ Argon เป็น **art director** ส่วน Nano Banana เป็นคนวาดชิ้นส่วน:
- **ใช้ Nano Banana วาดทั้งฉาก 1 ภาพเป็น key art** สำหรับเป็นเป้าหมายและเป็น style reference เท่านั้น ไม่ได้เอาเข้าเกม
- **ใช้ Argon สั่งวาดทีละชุด (sheet ละ 4 ชิ้น)** แนบ style sheet ทุกครั้ง แล้วให้ Argon ตรวจว่าภาพไหนสไตล์เพี้ยน เส้นบางเกิน หรือมีเงาบนพื้น แล้วสั่งวาดใหม่
- **ของที่วาดเป็นภาพใหญ่ภาพเดียวได้:** แผ่นพื้นแบบมองจากด้านบน (ground plate) เพราะพื้นแบนและไม่มีอะไรต้องเดินอ้อม ใช้แทน "สีพื้นเรียบ + decal" ได้เลย (ดูชุด E)

**แผน 4 วัน (วันละประมาณ 1 ชั่วโมง):**

| วัน | งาน |
|---|---|
| 1 | key art + style sheet จนได้ภาพที่ชอบ แล้วล็อกสไตล์ |
| 2 | ชุด A–B: ต้นไม้ + พุ่มไม้ (11 ชิ้น) |
| 3 | ชุด C–D: หญ้า ดอกไม้ ของเด่นประจำฉาก (12 ชิ้น) |
| 4 | ชุด E–F: decal + แหล่งแสง (9 ชิ้น) และวาดใหม่ชิ้นที่ตกรอบ |

## 6. เตรียมไฟล์ก่อนส่ง 08c

Nano Banana จะส่งภาพมาเป็น sheet 2×2 พื้นหลัง magenta ต้องตัดแยกเป็นชิ้นและทำพื้นหลังโปร่งใส งานนี้เป็นงานกลไกล้วน ให้ coding agent เขียนเครื่องมือก่อนเริ่ม 08c ได้ (ไม่ขัดกฎ "ห้ามวาดภาพแทน" เพราะไม่ได้วาดอะไรเพิ่ม):

```text
งานเครื่องมือ (ไม่ใช่ Stage เกม): tools/art/prep_cards.py (Python + Pillow)
- input: Art/Environment/ForestNight/Raw/<ชุด>_sheet.png + ไฟล์ mapping ลำดับช่อง → ชื่อไฟล์
- ตัด sheet ตาม grid 2×2 → ลบพื้นหลัง magenta แบบมี tolerance → ลดสีชมพูที่ติดขอบ (despill)
  → crop ให้เหลือแค่วัตถุ + เผื่อขอบ 8 px → บันทึกลง Incoming/<ชื่อไฟล์>.png
- รายงานชิ้นที่วัตถุแตะขอบช่อง (แปลว่าถูกตัด) หรือยังเหลือ magenta เกินเกณฑ์
- ห้ามแก้ภาพต้นฉบับใน Raw/ และห้ามวาดหรือเติมส่วนของภาพ
```

ลำดับรวม: **Gemini วาด → วางใน `Raw/` → รัน prep_cards → ตรวจด้วยตา → ส่ง 08c**

## สรุป

- **Argon วาดภาพเองไม่ได้** แต่สั่ง Nano Banana วาดและตรวจงานแทนคุณได้ จึงช่วยประหยัดเวลาคัดภาพได้มาก
- **ภาพฉากทั้งภาพใช้เป็นเป้าหมายได้อย่างเดียว** ฉากที่เล่นได้จริงต้องประกอบจากชิ้นส่วน ยกเว้นพื้นที่วาดเป็นภาพเดียวได้

   - วัด luminance contrast ของแต่ละกลุ่มกับพื้นรอบตัวในภาพ capture อัตโนมัติ
